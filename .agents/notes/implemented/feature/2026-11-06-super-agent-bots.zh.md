# Agent Note: DeepSeek Harness 上的超级智能体 Bot

Status: implemented

[English](2026-11-06-super-agent-bots.md) | 中文

## 问题

这套 harness 每个会话运行一个根 Agent。人打开会话、提问、审阅结果，对话结束后工作也就停止。没有持久身份持有例程，没有获得授权的无人值守工作单元，没有注意力预算，也没有按 Bot 的策略。

同类产品都收敛到这一层——有名字的队友、例程、审批与注意力状态——DeepSeek 自己的[超级智能体原型](https://github.com/deepseek-ai/dsh-superagent-prototype)也展示了它在这套 harness 上的形态。下面的工作把这一形态作为普通插件带进本仓库。

## 决定

### 记录

Bot 是持久记录，不是会话。一个 `bot` 存储域持有五张表：

| 表 | 保存 |
|---|---|
| `bots` | 名字、职责、工作区、路由会话、可选的执行 preset、工具白名单与硬性底线动作、状态 |
| `tickets` | 标题、指令、阶段、路由会话、执行会话、摘要、交接来源工单与 Bot |
| `memories` | 按 Bot 保存的笔记，以及写下它的工单 |
| `approvals` | 动作、确切载荷、SHA-256 摘要、状态、决定备注 |
| `notices` | 路由通知及其投递时间 |

域随表与可选字段的增加演进到版本 7；每个版本都能读取之前的版本。

### 会话

调用 `bot_create` 的会话成为 Bot 的路由会话。每条工单通过 `ctx.agents.create` 获得自己的根会话：Bot 的工作区、可选的 agent preset、`<bot>: <ticket>` 的标题，以及一条指令消息。执行者不是子智能体，因此比创建者活得久，并出现在侧栏。调用 `bot_report` 的执行者会与该工单记录的执行会话校验；报告更新工单，并以结构化通知到达路由会话。

### 工具

| 工具 | 调用者 | 作用 |
|---|---|---|
| `bot_create` | 任意会话 | 把当前对话绑定为 Bot 的路由会话，可带可选的 preset、工具白名单与硬性底线动作。 |
| `bot_list` | 任意 | 列出 Bot 与未结束工单数。 |
| `bot_open_ticket` | 路由会话 | 开工单并启动执行者。 |
| `bot_report` | 执行者 | 记录 `waiting`、`ready`、`blocked` 或 `failed` 与摘要。 |
| `bot_remember` | 路由或执行者 | 写入一条之后执行者会读到的持久笔记。 |
| `bot_handoff` | 执行者 | 在另一个活跃 Bot 上开工单并记录来源。 |
| `bot_request_approval` | 执行者 | 保存确切载荷与摘要并通知路由会话。 |
| `bot_decide_approval` | 路由会话 | 对一条待处理请求决定一次，并唤醒执行者。 |
| `bot_archive` | 任意 | 删除 Bot 及其工单、笔记、审批与通知。 |

### 授权与审批

审批把决定绑定到一份载荷及其摘要。协议默认是建议性的；开启 `enforceApprovals` 后，`tools/pre-execute` 钩子会拒绝工单执行者中未获批的受保护 shell 工具，除非该工单下已批准的请求携带确切命令。门禁只覆盖受保护工具的 `command` 参数。Bot 还可以指定工具白名单，同一门禁会在其工单内强制执行，同时始终保留上报工具；也可以指定硬性底线动作，在请求阶段即拒绝且之后不能批准。

### 注意力与记忆

`notices` 让路由消息持久化。安静时段会暂存它们；窗口外的定时器按对话发送一条摘要并把每条通知标记为已投递，因此重启不会重复。记忆笔记会以“Known context for this bot”为标题加到每个新执行者指令之前。

### 来源

`@deepseek-ai/dsh-bot-source-github` 通过 `gh` 轮询一个仓库。每个新 issue 记录一条候选；`observe` 只记录日志，`auto` 开工单。作者名单会过滤候选，写回在每个结果完成时评论一次，`bot_candidates` / `bot_accept_candidate` 负责审阅与提升。轮询循环的列表与评论效果以参数传入，测试因此能在没有 `gh` 进程的情况下用真实存储覆盖观察、自动、准入与写回；`autostart: false` 只挂载工具而不轮询。

### 面板

`bot` 会话投影把已记录的工具调用、结果与通知折叠为 `{ bot, tickets }`。`@deepseek-ai/dsh-client-ui-bot` 在输入框上方的停靠条渲染它：Bot 名称、工单数、待处理数，以及最多五行按阶段排序的工单。带有执行会话的行通过 `ctx.uiWorkspace` 打开它。

### 包与 preset

| 包 | 职责 |
|---|---|
| `dsh-bot` | 记录、工具、执行者启动、审批、注意力、记忆、交接 |
| `dsh-bot-source-github` | issue 轮询、候选、准入、写回 |
| `dsh-client-ui-bot` | 基于投影的输入框停靠条 |
| `dsh-bot-bundle` | `bot-router` 与 `bot-worker` preset、面板行、禁用的来源行 |

## 考虑过的替代方案

**扩展现有的自动化任务提案，而不是新增一层。** 可以让任务长出工单、执行者与审批。它输在：任务记录是用户写的“何时查看”规则，而 Bot 是一个带有授权和记忆、比任何规则都活得久的身份。

**每个 Bot 一个会话，不拆路由和执行。** 活动部件更少，对话本来就有上下文。它输在：长对话上的无人值守工作每轮都读已过期的缓存，一个阻塞步骤会拖慢所有到来的候选，而一段被污染的输入会带着整段历史和权限执行。

**用子智能体当执行者。** 它们已有持久会话和名字。它输在工单型工作上：子智能体树属于一个父级，并受 `maxActiveSubagents` 限制，而工单必须比创建者活得久、可以被重新打开，并作为独立根会话出现在侧栏。

**每个 Bot 一个 DSH profile。** 完全隔离且不需要新代码。它输在 Bot 必须共享人的工作区、凭据和面板，而且每次交接都会跨越进程边界。

**为每次审批使用独立的顾问模型。** 比提示词更强，但它先输给确定性的载荷比较；建议性协议加 shell 门禁覆盖了今天存在的风险，独立审查者仍然延期。

**只显示计数的面板。** 更简单也更安静。它输在人看不到 Bot 在做什么；停靠条现在最多列出五行。

## 延期

- 二元硬性底线之外的、按可逆性与数据敏感度划分的审批层级。
- 注意力严重程度、按用户的安静时段，以及一个间隔之外的摘要排程。
- 跨 Bot 的名册页面，以及每条工单的详情页。
- Loader 启动的夹具；组合测试挂载真实服务图，但不经过 Loader。
- 来源只在 Host 运行时轮询，而且只观察 issue。

## 后果

- Bot 可审计：每条工单说明其授权的来源、执行者与结果；每次审批说明它所决定的摘要。
- 无人值守工作有边界：安静时段、作者名单、先观察后自动，以及拒绝未批准命令的 shell 门禁。
- 存储域承载七个格式版本。每次新增都兼容，但 schema 与迁移面随每个功能增长。
- 审批只对受保护的 shell 工具强制执行；其他有后果的动作仍依赖执行者遵守协议。
- 工具白名单只在调用时拒绝，因此模型仍会在工具目录里看到被拒绝的工具，并从拒绝理由得知限制。
- 来源行为只有轮询，并随 Host 停止，因此 Bot 不是托管服务。
- 面板展示工作并能打开执行会话，但没有详情页，也没有跨 Bot 的名册。
